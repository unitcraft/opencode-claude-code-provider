# План 002 — фоновые задачи Claude Code в окне OpenCode

**Статус:** ЗАКРЫТ 2026-10-05.
**Где остановились:** Ф.0–Ф.2 закрыты и работают у владельца. Строка в системном промпте доходит
только до НОВЫХ сессий Claude Code (Claude Code хранит промпт сессии): у давно открытых вкладок (интегратор nova) её
не будет — им хватает описания `peer_watch` в списке инструментов и уведомления «stopped» в начале следующего хода.
**Проверено:** тесты `spawn`, `lib` (49 всего); живая проверка в песочнице (Ф.1, Ф.2).

## Цель

Окно claude-code ведёт себя с фоновыми задачами честно: ход не обрывается из-за них, модель не ждёт уведомления,
которое не придёт, а долгое ожидание (гейт на час) будит окно само.

Случай владельца 2026-10-05: интегратор запустил ожидание вердикта гейта в фоне (`until [ -f …done ]`,
`run_in_background`) и закончил ход «уведомление придёт само». Не пришло: гейт кончился зелёным в 12:33, окно стояло.
На сообщение владельца в 12:38 окно ответило пустым ходом за 5 с, а Claude Code успел начать работу и был оборван.

## Решения

| № | Решение | Кто | Дата |
|---|---------|-----|------|
| 1 | Не держать процесс Claude Code живым между ходами: запрос ведёт пакет ai-sdk-provider-claude-code, ход OpenCode кончается на его `result` — переписывать это хрупко | Claude | 2026-10-05 |
| 2 | Пустой `result` хода-уведомления выбрасывается из вывода процесса (свой `spawnClaudeCodeProcess`), само уведомление доходит до модели | Claude | 2026-10-05 |
| 3 | Долгое ожидание — у плагина opencode-peers (`peer_watch`; `peer_wait` уже занят ответом на вопрос): он живёт в сервере OpenCode, ждёт сам и будит окно письмом ([план 003 peers](https://github.com/unitcraft/opencode-peers/blob/main/doc/plans/003-watch.md)) | Claude, по «надо исправить» владельца | 2026-10-05 |

## Замеры (Claude Code 2.1.283, OpenCode 2.0.22, песочница)

- Ход запускает `sleep 45; date > метка` с `run_in_background` и кончается: метки нет и через 90 с — задача убита с
  концом хода (процесс Claude Code закрывается после `result`).
- Следующий ход продолжает сессию: Claude Code шлёт `task_notification` (stopped, «didn't finish before the previous
  session ended»), затем `result` с `num_turns: 0` без вызова модели, затем новый `init` и настоящий ход. Пакет кончает
  ход OpenCode на первом `result`: окно получает пустой ответ, процесс закрывается посреди настоящего хода.

## Фазы

### Ф.0 — замер

**ЗАКРЫТА 2026-10-05** (выше).

### Ф.1 — ход не обрывается

`src/spawn.js`: процесс запускается как в SDK (`spawn`, `windowsHide`), вывод идёт через построчный фильтр: `result`
выбрасывается, если с прошлого `result` был `task_notification` и не было ни одного ответа модели, и `num_turns` = 0.
Подключено к ходу окна и к `/compact`.

**Приёмка:** тест — пустой `result` после уведомления выброшен, настоящий сохранён; `result` с ответом или без
уведомления не трогается; строки, разрезанные между кусками, и UTF-8 внутри символа. Живая: ход 1 — фоновый
`sleep 600`, ход 2 — сообщение: ответ есть, модель знает об остановленной задаче.

**ЗАКРЫТА 2026-10-05.** Проверено: тест `spawn` (3); песочница — до исправления второй ход пустой за 5 с, после —
ответ «second» и «got a notice … didn't finish», в журнале «dropped the empty result of a task-notification turn».

### Ф.2 — модель знает и ждёт через peers

- Провайдер: постоянная строка в системный промпт Claude Code (окна claude-code): фоновые задачи останавливаются с
  концом хода, уведомления не будет; долгое ожидание — `peer_wait` (если подключён MCP opencode-peers), иначе
  ждать в ходе.
- Провайдер: если ход кончился с живыми фоновыми задачами (`background_tasks_changed`, не `ambient`), в конец
  ответа — заметка «остановлены с концом хода: …».
- opencode-peers: `peer_watch {command, note?, minutes?}` — плагин запускает команду ожидания у себя (сервер OpenCode), по её
  концу пишет окну письмо (код выхода, хвост вывода) с побудкой; переживает перезапуск сервиса (задание на диске).

**Приёмка:** тесты; живая — ход ставит `peer_watch`, ход кончается, команда завершается, окно просыпается
с результатом; ход с фоновой задачей кончается заметкой.

**ЗАКРЫТА 2026-10-05.** Сделано: `backgroundHint` (строка в `systemPrompt.append` всегда, вместе со строкой времени;
с MCP peers — про `peer_watch`, без него — «жди в ходе»); `backgroundWatch` — живые фоновые задачи хода по
`background_tasks_changed` (без `ambient`), в конце хода заметка `backgroundStopped` (en/ru); `peer_watch` — план 003
peers. Проверено: тест `lib` (набор задач, `ambient`, строка с peers и без); песочница — ход с фоновым `sleep 600`
кончился заметкой «Background tasks stopped with the end of this turn: Sleep for 10 minutes…»; ход вызвал
`peer_watch {sleep 20; echo watched-ok}` и закончился, через 20 с вкладка проснулась от письма и ответила «watched-ok».
