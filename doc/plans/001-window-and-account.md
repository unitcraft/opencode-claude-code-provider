# План 001 — окно контекста и учётка Claude по проекту

**Статус:** ЗАКРЫТ 2026-10-05.
**Где остановились:** Ф.0–Ф.2 закрыты и работают у владельца; явные пороги из
`C:/work/nova/.opencode/opencode-claude-code-provider.json` убраны 2026-10-05 после перезапуска сервиса —
единственный источник порога теперь конфиг OpenCode.
**Проверено:** тесты (45), живая проверка в песочнице (Ф.1, Ф.2).

## Цель

1. **Одно окно на двоих.** Claude Code сжимает свою память на пороге `autoCompactWindow` (по умолчанию Opus/Sonnet
   700K, Haiku 200K; в nv-lang 500K/500K/200K). OpenCode ничего об этом пороге не знает: он считает окно по
   `limit.context` модели (сейчас 1M у Opus/Sonnet) и показывает процент от него, а своё сжатие запускает около
   своего края. Нужно, чтобы процент в окне означал «сколько до сжатия», а OpenCode сжимал там же, где Claude Code
   (его сжатие провайдер и так передаёт Claude Code — `/compact`).
2. **Учётка Claude по проекту.** Сейчас учётка одна на все окна: `claudeConfigDir` провайдера в `opencode.jsonc`
   (переменная `CLAUDE_CONFIG_DIR` ярлыка на сервис не влияет — сервис один на все окна и поднимается первым
   запущенным ярлыком). Нужно, чтобы проект мог указать свою учётку.

## Решения

| № | Решение | Кто | Когда |
|---|---|---|---|
| 1 | Окно OpenCode для проекта задаётся проектным конфигом OpenCode (`.opencode/opencode.jsonc` в корне проекта: OpenCode ищет его вверх от папки вкладки, замер Ф.0) | замер | 2026-10-05 |
| 2 | Порог Claude Code и окно OpenCode берутся из одного места, чтобы не разойтись | владелец | 2026-10-05 |
| 4 | Источник — конфиг OpenCode: порог = `limit.context − compaction.reserved` модели (глобальный `opencode.jsonc` и проектный `.opencode/opencode.jsonc`); провайдер вычисляет из него `autoCompactWindow`, если тот не задан явно (опции провайдера или файл проекта провайдера). Процент в окне OpenCode = путь до сжатия; сжатие OpenCode провайдер и так передаёт Claude Code | по замеру Ф.0 | 2026-10-05 |
| 3 | `claudeConfigDir` можно задать в файле проекта провайдера `.opencode/opencode-claude-code-provider.json` (поверх `opencode.jsonc`) | владелец | 2026-10-05 |

## Замеры (OpenCode 2.0.22)

- 2026-10-05: OpenCode собирает конфиг из `opencode.json(c)` и `.opencode/` **вверх от папки вкладки** (не только
  в корне репозитория): в песочнице `work/nova/.opencode/opencode.jsonc` над репозиторием `work/nova/repo` задал
  `limit.context` модели — `model.list` вернул его. Для nv-lang это `C:/work/nova/.opencode/opencode.jsonc`.

- 2026-10-05: **OpenCode сжимает, когда контекст хода доходит до `limit.context − compaction.reserved`.** Песочница,
  Haiku, контекст ~28K, окно 40K: `reserved` 5000 (порог 35K) — сжатия нет; `reserved` 15000 (порог 25K) — сжатие
  перед следующим ходом. Значение `reserved` по умолчанию не измерено — задаётся явно.

## Фазы

`limit.context` у Haiku и два значения `compaction.reserved`; по тому, при каком размере хода OpenCode зовёт сжатие,
вывести формулу.

**Приёмка:** формула записана с замером; по ней выбрано, какие числа ставить в `limit.context`.

**ЗАКРЫТА 2026-10-05:** формула — в «Замерах», выбор — решение №4.

### Ф.2 — учётка по проекту

`claudeConfigDir` в слоях настроек провайдера (умолчание < `opencode.jsonc` < файл проекта); запрос идёт с
`CLAUDE_CONFIG_DIR` учётки проекта; карта сессий Claude Code — с учёткой (сессия одной учётки не продолжается
другой).

**Приёмка:** тест — вкладка проекта с файлом получает его учётку, без файла — учётку `opencode.jsonc`; сессия,
начатая под одной учёткой, при смене учётки начинается заново, а не падает. Живая проверка — два проекта с разными
учётками в одном сервисе.

**ЗАКРЫТА 2026-10-05.** Сделано: `claudeConfigDir` — ключ настроек провайдера (опции < файл проекта); запрос
всегда идёт с `CLAUDE_CONFIG_DIR` учётки окна (файл проекта, иначе опции, иначе `CLAUDE_CONFIG_DIR` сервиса);
карта сессий хранит учётку рядом с сессией (`<ses>@account`), `resumeFor` не продолжает сессию другой учётки
(старые записи без учётки продолжаются); `/compact` — так же.

Проверено: тесты `lib` (`resumeFor`: та же учётка, другая, запись без учётки; учётка из файла проекта главнее
опций). Живая проверка — один сервер песочницы, глобальная учётка nv-lang: вкладка в репозитории с файлом проекта
`{"claudeConfigDir": "<пустая папка>"}` — Claude Code ответил «Not logged in» (взята учётка проекта); новая
вкладка без файла — ответ «Yes», в карте сессий `@account` = nv-lang. Заметка: прямой вызов провайдера из оболочки
Claude Desktop не годится для проверки — переменные хоста (`CLAUDE_CODE_*`) ломают вход дочернего Claude Code.
